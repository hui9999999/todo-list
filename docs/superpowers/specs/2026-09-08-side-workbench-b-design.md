# 侧边工作台 B 方案设计

日期：2026-09-08

## 目标

把当前“统计左栏 + 任务中栏 + AI/花田右栏”的固定页面改为“左侧工作区导航 + 中央任务区 + 按需打开的右侧任务工作台”。用户打开应用后先专注处理任务，只有在查看或编辑某个任务时才展开详情；统计、AI、花田和垃圾站进入各自独立的工作区。

本次改版保留现有任务数据结构、任务操作和本地存储，不改变任务的状态、周期、截止时间、子任务、计时、导入导出和 AI 指令语义。

## 用户界面结构

### 应用外壳

页面分为三层：

1. 顶部栏显示当前工作区名称、日期/天气摘要、主题和设置入口。
2. 左侧导航显示工作区入口：今天、本周、日历、统计、AI 助手、我的花田、垃圾站。当前入口有明确的选中状态和文字标签。
3. 中央内容区只渲染当前工作区。任务工作区包含新增任务、筛选、搜索、分组和分页；其他工作区承接现有对应面板。

任务详情不再占据固定右栏，而是在选择任务后从右侧覆盖打开“任务工作台”。工作台包含标题、状态、失败原因、优先级、截止时间、备注、子任务、专注计时和删除等现有详情操作。

### 工作区导航

新增一个视图状态 `state.view`，默认值为 `today`。导航点击只更新视图和当前导航选中状态，不刷新页面，也不清空任务筛选、搜索词或分页位置。

- `today`：显示当前任务列表及今日聚焦。
- `week`：复用现有类型/日期筛选，显示本周任务。
- `calendar`：显示日期选择与按日期查看任务的入口。
- `stats`：显示原统计卡片、趋势图和分类图表。
- `ai`：显示 DeepSeek 提问/建任务区域及对话结果。
- `garden`：显示花田图片、阶段说明和奖励动画。
- `trash`：显示垃圾站列表、恢复和清空操作。

设置仍由顶部设置按钮打开，不作为任务工作区的一部分。天气保持顶部摘要，点击后继续打开天气弹层。

### 任务工作台抽屉

点击任务行、任务标题或任务操作中的“详情”入口时：

- 设置 `state.selectedId` 并给抽屉添加打开状态。
- 抽屉从右侧进入，桌面端宽度约 360px；任务列表保留在背景中但不应被误操作。
- 抽屉顶部提供标题“任务工作台”和关闭按钮。
- 抽屉外的遮罩、顶部关闭按钮和 Escape 键都能关闭抽屉。
- 关闭时只清除 `state.selectedId`，不改变任务数据。
- 任务被删除、恢复或导入替换后，如果当前选中任务不存在，抽屉自动关闭。

抽屉沿用现有详情保存方式：文本/备注失焦保存，状态、优先级和截止时间即时保存，明确的“保存”按钮继续保留作为用户可见确认入口。任务完成、失败、删除和计时等现有动画/提示继续触发。

## 响应式行为

- 宽度 `>= 1080px`：左侧导航显示图标和文字，抽屉宽度约 360px，覆盖中央内容的右侧区域。
- 宽度 `720px–1079px`：左侧导航默认收窄为图标栏，可通过顶部按钮展开；抽屉仍从右侧覆盖打开。
- 宽度 `< 720px`：导航变为左侧覆盖菜单；任务工作台变为接近全屏的右侧页面，打开后任务列表不可操作，关闭返回原滚动位置。
- 所有操作入口保留可见文字或可访问名称，不依赖悬停才能发现。

抽屉和导航都使用现有 CSS 变量，继续支持 light、dark、purple、green、pink、teal、orange、gold、silver 等主题。重排后不再依赖固定三栏高度，中央任务区允许自然滚动。

## 实现边界

### HTML/CSS

在 `index.html` 内将现有固定三栏外壳调整为：

- `.app-shell`：整体布局容器。
- `.workspace-nav`：左侧工作区导航。
- `.workspace-main`：中央内容区及顶部工具栏。
- `.task-drawer` 与 `.drawer-backdrop`：右侧任务工作台及遮罩。
- `.view-panel[data-view]`：今天、本周、日历、统计、AI、花田和垃圾站面板。

现有任务行、统计卡片、AI 控件、花田图片和垃圾站 DOM 尽量复用，减少行为重写。原来的详情弹窗 DOM 迁移为抽屉 DOM，不复制一套任务编辑逻辑。

### JavaScript

增加几个清晰的边界函数：

- `setView(view)`：切换视图、更新导航选中状态并渲染当前面板。
- `openTaskDrawer(id)` / `closeTaskDrawer()`：维护选中任务和抽屉状态。
- `renderWorkspaceNav()`：渲染活动入口和数量提示。
- `renderCurrentView()`：只显示当前视图需要的面板。

现有 `render()` 继续负责任务列表和统计数据，详情字段绑定逻辑集中到抽屉初始化函数。`load()` 对旧数据缺少 `view` 的情况回落到 `today`；`save()` 可保存当前视图，也可以把视图视为界面偏好，不影响任务数据兼容性。

### 数据与兼容性

不改变 `my-todo-list-v3` 中任务对象字段。旧的 localStorage 数据直接加载；新增字段都是可选字段。导入数据后继续使用现有 `normalize()`，并在选中任务不存在时关闭抽屉。此次改版不处理图片去重、DeepSeek 后端代理或导出格式扩展，这些属于独立后续工作。

## 可访问性与错误处理

- 导航使用按钮，并提供当前工作区的 `aria-current` 或等价选中状态。
- 抽屉使用 `role="dialog"`、可见标题和关闭按钮；打开时将焦点放到标题或第一个可编辑字段，关闭后恢复到触发任务行。
- 抽屉打开期间，Tab 顺序限制在抽屉内；Escape 关闭抽屉。
- 空任务、空垃圾站和天气/AI 网络失败沿用现有提示，内容显示在当前工作区而不是悬空在隐藏面板中。
- 任何渲染周期都检查当前视图和 `selectedId` 是否仍然有效，避免删除任务后残留详情。

## 验证方案

实现后进行以下检查：

1. 用 Node 解析内嵌 JavaScript，确认语法无误。
2. 启动本地静态服务器，检查首次加载、主题切换、天气失败提示和控制台错误。
3. 手动验证新增、编辑、完成、标记未完成、删除/恢复、子任务和专注计时，并确认抽屉开关不改变数据。
4. 逐一点击七个导航入口，确认每个工作区显示正确，切回任务区后筛选和搜索状态符合预期。
5. 在桌面、平板和手机宽度检查导航、抽屉、遮罩、滚动和键盘 Escape 行为。
6. 导入旧 JSON 备份并重新打开页面，确认任务数据兼容，默认视图为“今天”。

完成标准是：中央任务区成为默认焦点；任务详情只有选中任务时出现；所有原有功能都能从导航或抽屉到达；桌面和窄屏均无内容重叠、裁切或无法关闭的浮层。
