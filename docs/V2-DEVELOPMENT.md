# 2.0 开发与验收

P0–P4 已落地本地开发版，阶段结果与发布边界见 [P1–P4 验收说明](P1-P4-ACCEPTANCE.md)。1.0 根目录 `index.html`、原浏览器数据和本地 ZIP 快照保留；2.0 不读取旧版 localStorage，也不迁移旧模型 Key。

## 启动

Windows 需要 Node.js 22.12+ 或 24、Python 3.11+ 和运行中的 Docker Desktop。

```powershell
.\scripts\start-v2.ps1
```

此脚本启动独立 PostgreSQL/pgvector 和开发邮件服务，安装锁定依赖、执行 Alembic 迁移并生成本地主密钥，然后在后台启动前后端与独立 worker。访问：

- 应用：http://localhost:5174
- 开发邮箱：http://localhost:28025（密码重置邮件到此处查看，不投递到真实邮箱；注册不发送邮件）
- API 文档：http://localhost:8000/api/docs

同一来源必须始终使用 `localhost`，避免换成 `127.0.0.1` 后 Cookie／Origin 不一致。5173 是本机已有项目的端口，2.0 使用 5174。

第二次启动可用 `-SkipInstall` 跳过依赖安装；端口已有服务时会提示打开应用或先停止。停止自己启动的前后端与 worker：

```powershell
.\scripts\stop-v2.ps1
```

数据库容器和持久卷仍保留。可用 `docker compose stop` 暂停容器；后续 `docker compose up -d` 继续使用原数据。

需要自定义配置时复制 `backend/.env.example` 为 `backend/.env`。这里的数据库密码与无 TLS SMTP 仅服务于本地开发；公开部署需要独立秘密、HTTPS、`COOKIE_SECURE=true`、正式 SMTP，并完成 P4 发布检查。

## 手动运行

```powershell
docker compose up -d --wait
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd backend
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

另一个终端：

```powershell
cd frontend
npm ci
npm run dev
```

后端仅使用受限 `todo_app` 角色，迁移使用 `todo_owner`。私有业务表启用 FORCE RLS，并在事务内设置用户 ID；会话与认证表由认证模块管理。不会自动建表或在服务启动时运行迁移。

## 基础任务与迁移规则

- 邮箱或电话号码注册、自动登录、登录、退出与邮箱密码重置；注册无需邮箱验证、短信验证码或人工审核；密码使用 Argon2，Cookie 为 HttpOnly，写操作验证同源与会话 CSRF。
- 工作、生活、学习、未分类任务；备注、优先级、状态、日期或带时区的精确截止时间；多层子任务。父任务有待办或进行中的子任务时不能收尾；所有子任务结束后可明确选择父任务结果，失败子任务的实际结果保留。
- 快速添加、新建任务与子任务默认账户时区当天 23:59 截止，可以修改或选择不设截止；已有任务编辑不补填默认时间。API 新建时省略截止字段会使用默认值，显式传入空值表示不设截止。AI 新建任务省略截止字段时，操作预览会补齐同一默认时间，确认后保存。
- 今日安排复用原任务，重复加入只保留一次，截止日期不变。
- 侧栏统一“清单”入口，页面内切换今日清单、本周清单、本月清单、年度清单。周一为一周起点，月份和年度按自然月、自然年；截止时刻按账户时区转换为日期。各周期包括该范围的截止任务和今日手动安排，逾期未完成的任务继续显示；无截止且未安排的任务集中在“待安排”区。分类、状态、搜索、隐藏任务与父子层级继续生效。切换不改写任务，刷新保留网址中选中的周期；账户跨午夜后自动更新当前范围。
- 日历上方“选择日期”提供年、月、日滚轮，支持鼠标/触控板、手机上下滑动及键盘 ↑↓、PageUp/PageDown、Home/End。选择实时同步日期高亮与当天任务，切换月份/年份时自动约束月末天数，按账户时区初始化及返回今天；完成后保留所选日期。同月选择复用当前月份数据，跨月读取只接受最新请求，失败可以重试；只有点击“加入此日安排”才写入日计划。
- 详情提供实际变更事件与快照；改名和重新打开不会覆盖过去的完成记录。修改携带版本号，过期版本返回 409。
- 垃圾站按删除批次恢复父子任务；P4 支持确认后永久删除，并由 worker 清理超过 30 天的垃圾站任务及关联证据。
- 1.0 导入支持旧任务数组及对象的 `tasks` 数组。旧 `fail` 保留为失败，`period` 不创建重复规则，计时暂停并保留剩余秒数。没有真实完成时间时保留未知，不编造事件。
- 导入展示错误、警告与数量；有错误时整个批次不能确认。修正 JSON 后重新预览；不静默跳过异常项。不识别的字段、顶层垃圾站和设置不导入，预览明确提示。
- 文件摘要与批次锁防重复确认，改变默认范围不能把已确认文件再导入一次。旧 ID 全部重新分配，父子关系映射保留。
- 2.0 JSON 备份包含任务、项目、依赖、历史快照和今日安排。恢复重新映射任务与垃圾站批次，历史标注导入来源，并追加当前导入事件；凭据不包含在账户级 JSON 中。
- 兼容 1.0 导出仅含有效任务；`doing/cancelled` 映射为 `todo`，新范围、安排和事件不能回填。1.0 自身可能补造未知完成时间，因此如需保留时间证据应保存 2.0 备份。

### 任务状态与收尾（2026-10-05）

- 状态仍为待办、进行中、已完成、失败、已取消。待办可以开始，也可以直接完成；失败表示本次执行未达到目标，取消表示主动不再执行。逾期是根据截止时间计算的提示，不会自动修改任务状态，AI 调用失败也不会修改业务任务状态。
- 新建或标记失败必须填写非空原因；提供常用原因和自由说明。失败任务通过“重新尝试”回到待办，清空当前原因，原失败状态和原因保留在事件快照中，详情显示此前失败原因。旧备份中缺少原因的失败记录仍可导入和重试，不补造原因。
- 卡片按状态显示“开始／完成、重新尝试、重新打开”；标记失败和取消任务位于更多菜单。失败、取消的卡片不显示完成勾选，详情中也需先保存为待办或进行中再完成。取消操作先明确确认。
- 父任务的待办或进行中后代会阻止完成、失败和取消。后代均已结束且包含失败项时，完成操作列出失败任务及原因，用户选择“整体目标已完成／整体未达成／不再执行”。确认整体完成须携带失败后代的 ID 与版本；原因或结果被其他操作修改时拒绝过期确认。父任务关闭后，继续处理子任务须先重新打开父任务。
- 必要依赖未完成、失败或移入垃圾站时，卡片和详情显示“受阻”及具体原因；阻止开始和完成，仍可标记本任务失败或取消。依赖已完成或已取消可继续；依赖移入垃圾站需恢复或明确解除，不能通过删除悄悄满足依赖。受阻由实时依赖计算，不增加数据库状态；修改依赖会刷新卡片提示。
- 手动 API 与 AI 提案使用相同校验。AI 不能编造失败原因；父任务包含失败后代时，提案明确展示风险，由用户确认后提交，并再次校验相关版本。今日建议沿用同一依赖受阻规则。
- `GET /tasks` 和单任务响应新增派生 `workflow`，包含 `blocking_dependencies`、`active_children`、`failed_children`。这些字段不进入持久化快照和备份；`PUT /tasks/{id}` 的 `confirmed_failed_children` 只用于本次结果确认。

验证：后端 `pytest -q tests/test_task_workflow.py`；桌面与手机 `npm run test:e2e -- task-workflow.spec.ts task-cards.spec.ts task-editor-race.spec.ts core.spec.ts`，以及 `npm run build`。

## 统计图表

任务分类包含工作、生活、学习和未分类。学习分类可用于快速添加、任务编辑、分类筛选、项目、周期任务、历史搜索、记忆与 AI 任务提案，并在完成分类环形图中独立展示。2.0 备份保留学习分类，旧版 JSON 导入可选择默认归入学习；兼容 1.0 导出与其他分类一样无法保存分类。

统计页支持近 7／30／90 天、本月与自定义日期，按账户时区展示完成与新增柱状图、专注折线图、分类占比环形图、星期节奏、完成优先级、当前状态、待处理优先级和项目进度图。长时间范围自动按 7 天或 30 天汇总；悬停或键盘聚焦可读数，完成趋势、分类和任务分布可点击查看对应明细。

期间完成任务数按任务去重，趋势与分类按完成事件计数；重新打开再完成会增加完成次数。没有记录的日期补零，上期比较使用相邻的同长度时间段。专注按会话开始日期归属，取消会话不计入。当前状态、优先级、项目与逾期不受期间筛选影响。前端构建、统计接口测试和桌面／手机图表测试分别运行 `npm run build`、`pytest -q tests/test_statistics.py` 和 `npm run test:e2e -- statistics.spec.ts`。

## 数据管理与个人账户

工作区导航保留一个数据管理入口，内部包含“导出数据、备份与导入、垃圾站”。垃圾站保留原有恢复父子任务、永久删除确认与 30 天清理规则。桌面侧栏底部和手机顶部的个人账户入口提供账户信息与设置。旧 `/trash`、`/settings` 链接分别跳转到 `/data?tab=trash`、`/account`。

任务报告支持 Excel `.xlsx`、PDF `.pdf`、Word `.docx` 与 UTF-8 BOM CSV `.csv`。可按创建、完成、更新或截止时间筛选，日期可单边或双边填写，结束日期包含账户时区当天；快捷选择全部时间、近 7／30 天与本月。创建时间优先采用旧版导入的真实创建时间，完成与截止筛选排除对应时间未知的任务。报告按任务当前字段统计，每条任务计一次，包含隐藏任务，默认排除垃圾站，可选择包含垃圾站与备注。

`GET /api/v1/exports/preview` 返回同一筛选条件的任务数量与分类／状态分布；`GET /api/v1/exports/report?format=xlsx` 下载报告，参数为 `start`、`end`、`date_field`、`scope`、`status`、`include_trash`、`include_notes`。预览、图表和下载使用同一查询，始终限定当前账户。Excel 使用可筛选明细表与原生图表，时间／分钟保留类型，用户文本不会作为公式执行；PDF／Word 使用中文图表与可分页的明细、备注。CSV 对可能触发公式的文本加单引号。

完整恢复仍使用“备份与导入”里的 2.0 JSON，不受报告筛选影响。报告单次最多 10000 条任务，PDF／Word 超过 200 万正文字符时要求缩小范围、取消备注或改用 Excel，不截断任务或备注。后端验证运行 `pytest -q tests/test_reports.py`，桌面与手机验证运行 `npm run test:e2e -- data-management.spec.ts core.spec.ts`。当前环境缺少 LibreOffice／Word 的自动排版渲染器，Word 已验证 OOXML 内容、图表图片与结构，仍需在 Word 或 WPS 中核对分页。

## AI 与后台功能

聊天输入按 Enter 发送、Shift + Enter 换行；中文输入法选字时的回车不发送，空消息、重复按键和正在处理请求时也不会重复发送。

AI 助手可在聊天中创建、修改和删除任务。输入框上方提供三个任务操作入口；自然语言请求先生成操作预览，确认后写入任务并刷新清单，支持撤销。修改预览显示旧值与新值，未指定的字段保留原值；删除移入垃圾站，包含子任务。新建未指定截止时间时默认账户当天 23:59。

已验证工具调用的模型通过 `respond` 返回提案；仅验证聊天能力的模型使用 JSON 指令通道，经过同一字段、所有权、版本与确认校验。JSON 原始数据不展示在聊天中，格式不合法或流被截断时不执行任务变更。验证命令：`pytest -q tests/test_ai_task_operations.py`、`npm run test:e2e -- ai-task-operations.spec.ts`。

聊天支持选择多个附件、拖入文件和粘贴截图，也可仅发送附件。支持 Word `.docx`、PDF、Markdown（`.md/.markdown`）、JSON、TXT、CSV 和 PNG/JPG/JPEG/WEBP 图片。旧版 `.doc` 需先转换为 `.docx`；损坏文件、无效 JSON 和加密 PDF 会返回明确错误，保留草稿供修正。每条消息最多 5 个附件，单个最多 8 MB，总计最多 20 MB。

Word 读取正文、表格、页眉与页脚；插图提示未读取。PDF 读取前 40 页，并对其中最多 6 个没有文本的扫描页进行本地 OCR。图片也进行本地中英文文字识别。每个文件最多保留 60000 个字符，每次模型请求对单个附件最多使用 12000 个字符，消息文本总窗口约 24000 字符；截断、扫描页识别和未读取页数会明确提示给用户或模型。PDF 中有文本的页面只读取文字，图表和嵌入图片的画面不解析。

默认聊天模型可以总结提取的文字并生成任务提案。照片与图片画面需在设置 → 高级设置中执行“测试图片识别”，通过后才向该模型发送图片；一轮最多纳入最近 5 张图片。图片无可读文字且模型未验证识图时，助手说明限制，不能猜测画面。识图测试使用随机排列的本地色块图，并计入主动测试用量。

附件提取在服务端进行，客户端不能提交自行伪造的提取结果。只在所属消息中保存提取文本和压缩图片，不保留 Word/PDF 原文件；消息列表只返回附件名称、大小、页数与读取提示。附件与对话共享账户隔离，删除对话或遗忘其来源时清理相应附件数据；附件不会进入任务备份导出。数据库变更通过 `alembic upgrade head` 应用，也可用 `scripts/restart-v2-backend.ps1` 完成迁移和本地后端重启。

附件验证：`pytest -q tests/test_chat_attachments.py`、`npm run test:e2e -- chat-attachments.spec.ts`。OCR 模型包含在 Python 依赖中，首次使用需加载模型，扫描文件处理时间长于普通文字文档。

P1–P4 功能、真实接口待验项及限制详见 [阶段验收](P1-P4-ACCEPTANCE.md)。手动启动时还需要在独立终端运行 worker，否则对话作业、自动推荐、索引、周期及清理不会执行：

```powershell
cd backend
.venv/Scripts/python.exe -m app.worker
```

`GET /api/v1/health` 返回数据库状态和 `worker_alive`。本地主密钥保存在 `backend/.runtime/credential.key`，由启动脚本创建；不要删除正在使用的主密钥，否则现有加密凭据无法解密。源码与日志默认排除运行时文件。


## 无需验证的注册

邮箱或电话号码加密码即可注册，邮箱无需真实可投递，号码无需短信验证，账号不需要人工审核。注册页面分为手机号和邮箱两种方式，可选填昵称（最多 30 个字符，允许重名），个人账户及头像优先使用昵称；未填写的账户继续显示登录账号。要求设置并确认密码，字段格式与两次密码一致性在表单内校验。时区根据设备自动识别，注册时不必选择，之后可在个人账户中修改。注册接口返回登录 Cookie 与 CSRF，前端直接进入今日工作台。邮箱统一转为小写，电话去除空格、括号和连接符；中国大陆 11 位手机号码与其 +86 格式视为同一个账号，国际号码支持国家区号。

注册和登录接口统一使用 `identifier`，同时兼容旧 `email` 参数和 `phone` 参数。已有邮箱账号及未完成邮箱验证的旧账号均可按原密码登录。重复注册返回冲突，不能覆盖原密码。原有密码哈希、登录限流、HttpOnly Cookie、同源检查与 CSRF 保持有效。

个人账户的名字旁可直接修改昵称。`GET/PUT /account-profile` 返回昵称及当天剩余修改次数；按账户时区的自然日最多成功修改两次，零点重置。注册填写昵称、取消编辑、保存相同昵称及失败请求不计次。修改记录单独持久化并按账户隔离，账户行锁保证多设备并发不能超额；第三次修改返回 429，删除账户同时清除修改记录。昵称最多 30 个字符，修改时不能为空，邮箱和电话号码仍用于登录与账户删除确认。

## 偏好、城市选择与提醒

新账户的记忆、智能追问、资讯推荐、今日建议、到期通知和天气默认开启；已有账户保存的开关选择保持有效。天气城市按区域提供可滚动列表，支持搜索和自定义城市；修改后保存设置生效，较早的天气请求不能覆盖最新城市的结果。

天气显示在今日标题下方。中文城市定位失败时使用无声调拼音再次查询（如娄底 → loudi），显示名仍保留用户选择的中文名称。城市无法定位、上游故障、加载中和未开启均显示明确状态；支持重试、刷新和跳转城市设置。

到期通知使用应用内卡片，展示优先级、截止时间和任务名称，可查看任务、逐项忽略或关闭全部提醒；真实提醒 20 秒后自动收起。多个到期任务合并展示，系统通知也合并为一次；按账户、任务版本和当天日期去重。未授权或系统通知失败时，仍显示应用内提醒。设置中显示授权状态、允许用户主动请求系统通知并预览应用内卡片；预览不产生真实系统通知，也不扣除任务提醒次数。浏览器自己的授权弹窗外观由浏览器决定。

个人账户显示所用邮箱或电话号码；删除账户需要输入对应账号。`confirm_identifier` 适用于所有账号，旧 `confirm_email` 仅兼容邮箱账号。找回密码仍需接收邮箱重置链接；目前未提供电话号码找回密码通道。

迁移 `a26100211000` 增加唯一电话号码字段、允许邮箱为空、约束每个账号仅使用一种标识，并取消已有账号的激活门槛。回滚前必须先迁移电话账号，避免丢失身份数据。
