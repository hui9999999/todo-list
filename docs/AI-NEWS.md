# AI 资讯整理

点击资讯页的“更新资讯”，使用账号当前绑定的 AI 模型整理内容。设置关注主题后，AI 先理解主题并生成最多 4 条检索词及具体领域词，同时从已配置来源中选择相关专业栏目，再结合公开搜索结果和近期订阅源进行筛选。专业栏目的文章进入后续语义筛选，避免检索词过度缩窄主题而漏掉医学诊疗等相关内容。未设置关注主题时，从综合订阅内容中整理。

每批最多 5 条，允许少于 5 条或没有合格内容。文章的核心事件必须与主题直接相关，不能仅因为社会新闻顺带提到领域词就收录。AI 合并同一事件的报道，逐条生成中文标题、摘要与最多 3 条重点。输入材料是来源的标题及摘要，页面明确标注“依据来源摘要”，不声称阅读全文。

## 来源与日期

模型只能引用服务器提供的来源编号。服务器根据编号保存原始标题、原文链接、来源名称及可靠的发布日期，拒绝不存在的编号、额外网址字段、不安全地址和摘要中的网址。每条可以引用 1–3 个来源。搜索 RSS 的日期可能是抓取日期，不用作文章发布日期；缺失时显示“发布日期未提供”。

来源信息保存在现有资讯记录中，无数据库迁移。API 单独返回来源、摘要与重点，同时向旧客户端保留可读的 `reason` 摘要与主要原文链接。主题筛选读取经过验证的 AI 分类，避免再次要求标题包含完整的“医药相关”等字样。已有普通资讯继续兼容。

## 更新与错误

页面自动查询后台进度，完成后加载新内容；刷新或重新进入可以恢复进行中的整理。后台失败、模型未配置、预算不足、检索不可用及没有新的合格内容都有明确反馈。进行中的任务合并处理；已完成任务经过短暂冷却后可以再次更新，不再永久复用同一天的已完成请求。

每个模型调用沿用后台调用次数、Token 预算与用量记录；关注或模型设置改变、模型连接关闭后停止发布旧结果。历史来源去重涵盖同一条资讯的所有来源；收藏及主题、来源反馈继续保留。

当前搜索使用已有的免费公开搜索入口，其中文召回和新闻时效有限，不能保证覆盖所有主题。订阅源仍是补充渠道，本次增加中新网健康订阅。AI 不以自身知识补写检索中不存在的事实、数字或发布日期。

## DeepSeek 暴露的检索渠道问题

用户关注 `deepseek` 后再次零结果（设置版本 13）。实际普通 Bing RSS 查询返回官网、下载页、百科和产品页面，并非新闻检索；国际参数或追加 news 也未可靠改进。生产网络探测中 Google News、GDELT、Exa、HN Algolia、Tavily 连接失败或超时，百度与搜狗遇到验证码。没有绕过验证码。不能再用单篇手工补充声称自动检索已经有效。

已增加可选博查 Web Search API 接入，使用固定 HTTPS 端点、近一个月范围与受限摘要。生产服务器无密钥请求返回 401，只证明网络可达，不证明搜索质量。默认仍为 `rss`，不会自动开通搜索账号、注册充值或用模型密钥调用搜索；必须显式选择 `bocha` 并配置独立密钥后才使用。每次资讯整理至多 4 次原名发现查询加 4 次不重复补充查询，每次最多 10 条结果；搜索费用由搜索服务计费，和模型调用额度分开。

配置示例（保存在服务器私有 `cloud.env`，不要提交实际密钥）：

```dotenv
NEWS_SEARCH_PROVIDER=bocha
BOCHA_SEARCH_KEY_FILE=/app/.runtime/bocha-search.key
```

可替代地使用 `BOCHA_SEARCH_API_KEY` 环境变量，密钥类型为 `SecretStr`。密钥文件应仅运行账户可读（如 0600），放在现有持久运行卷中；API 与 worker 都通过 Compose 读取配置。环境配置变更后需重新创建两个服务。无密钥、无权限或认证失败明确报配置错误，不伪装为空结果；失败输出不包含上游原文或密钥。

搜索 API 的 `datePublished` 保留为发布日期；RSS `pubDate`、API `dateLastCrawled` 不能作为发布日期。正式搜索结果允许近 30 天报道，现有订阅源保持 7 天窗口。零条摘要返回 `insufficient_sources`，页面说明“暂未取得相关报道／不代表没有资讯”；只有已生成摘要在并发去重后均已存在时才明确说“都已展示”。历史错误零结果提示也在读取状态时更正，无需改写历史数据库。
