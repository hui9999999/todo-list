# 2.0 Bug 检查与修复

日期：2026-10-01。检查范围：P1–P4 的任务安排、设置、模型选择、并发建议、周期规则和后台队列；使用隔离测试账户及 PostgreSQL 测试库，不改 1.0 页面和用户任务。

## 已确认的问题

| 问题 | 触发与原行为 | 修复 |
| --- | --- | --- |
| 测试新模型后选择被覆盖 | 已保存旧模型，再选择并测试新模型；刷新状态时把表单重新填成旧默认值，随后保存的仍是旧模型 | 初始化时读取默认值；测试与运行状态刷新保留当前草稿；连接失效时才清空选择 |
| 通知开关未立即同步 | 在设置页保存开启或关闭，工作台定时器仍读旧设置，直到导航或重载 | 保存后向工作台同步设置快照，天气与通知读取新状态；未保存的表单不改变已生效设置 |
| 今日建议忽略已有安排 | 日容量 120 分钟，已安排 90 分钟；仍可能重复推荐该任务或占满额外 120 分钟 | 扣除当前安排及有效待确认建议的已知估时；已安排任务不再推荐；未知估时仍明确标注 |
| 约束变化后旧提案仍可确认 | 修改时区、工作时段或每日容量，旧条件下的提案仍返回确认成功 | 这些变化更新上下文版本；旧提案返回冲突，过时建议标为失效并允许重新生成 |
| 并发建议重复发布 | 两个作业同时生成，读取相同旧快照，各发布 5 条，得到 10 条重复建议 | 发布时在用户锁内重新读取现有建议和容量，防重复且限制有效建议数量 |
| 未来周期模板漏校验项目归属 | 开始日期在未来时，其他用户项目 ID／不存在的项目 ID 能保存，到生成实例时才报错 | 创建和修改规则时即验证项目归属，返回 404，不保存错误规则 |
| 一个账户异常阻塞其他账户 | 旧无效周期规则在调度末尾抛出异常，整个 tick 停止，后续用户没有执行机会 | 每个账户独立执行与异常处理，记录必要错误信息并继续其他账户 |

并发重复通过两个真实后台执行线程复现；约束、容量和项目问题通过 API 与真实 PostgreSQL 复现。新对话残留也进行了浏览器检查，目前未复现，未作为已确认问题修改。

完整后端回归 50 项通过；前端类型检查与生产构建通过；桌面／手机完整浏览器回归 10 项通过。连续测试触发过认证限流，等待窗口释放后完成全量复测，没有放宽限流。更多结果见 [P1–P4 验收说明](P1-P4-ACCEPTANCE.md)。开发服务重启加载修复，数据库卷和账户会话保留。
