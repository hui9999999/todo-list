# 周报与月报

入口：统计 → 周报与月报。默认开启自动生成，用户可分别关闭周报或月报。

- 每周一账户当地时间 09:00 生成上一自然周（周一至周日）的周报。
- 每月 1 日当地时间 09:00 生成上一自然月的月报。
- 选择周内任意日期或一个月份即可手动生成；同一周期再次生成更新原报告。
- 尚未结束的周期标注“截至目前”，自动生成会在周期结束后补全它。
- 历史报告是生成时的快照，包含任务完成/新增趋势、专注时长、分类分布、与上一周期比较、复盘摘要、完成事项和后续安排。未结束周期按上期相同天数比较。
- 复制报告可用于整理或分享复盘。

自动生成由现有后台 worker 执行，页面关闭后仍会运行。部署时保持 `python -m app.worker` 服务运行。服务暂停时报告不会生成，恢复后按持久化游标补生成错过的周期；每次调度最多补四个周期，后续轮询继续补齐。已有账户从功能启用日开始，新账户从注册日起开始；关闭后重新开启仅从下一个发生时间继续。

报告直接汇总真实任务事件与专注记录，不需要连接对话模型，也不消耗模型调用配额。完成任务按任务去重，图表分类及趋势按完成事件计数；已移入垃圾站的任务不进入新生成的任务统计。专注归属会话开始日期，取消会话不计入时长。后续安排显示生成时仍未完成、截止日期不晚于报告期末（开放周期截至当天）的任务。

数据迁移 `a26100210000` 新增 `period_reports` 和 `report_schedules`，两表强制执行租户 RLS，并在账户删除时级联清理。永久删除任务会从历史报告中清除对应标题与明细，保留不含标题的历史汇总；数据库备份恢复重放删除日志时同样清理报告明细。

接口：

- `GET /api/v1/period-reports?kind=weekly&offset=0`：历史报告，每页最多 20 条，可选类型。
- `POST /api/v1/period-reports`：`{kind: "weekly" | "monthly", date: "YYYY-MM-DD"}`，手动生成并保存。
- `GET /api/v1/period-reports/{id}`：报告详情。
- `GET /api/v1/period-reports/schedule`：自动生成设置与下一次生成日期。
- `PUT /api/v1/period-reports/schedule`：`{weekly_enabled, monthly_enabled, version}`，乐观版本校验。

调度游标和入队在同一事务保存，后台任务使用固定周期去重键、租约和失败重试。同周期报告唯一约束与账户锁避免自动和手动生成产生重复。
